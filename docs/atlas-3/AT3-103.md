# AT3-103 — Execution identity + evidence attestation + proof v2 foundation

Isolated Atlas 3 runtime (Ultimate Atlas planning alias ULT-01a; the planning
documents are proposed separately and are not part of this package). Does not
mutate certified 2.x surfaces. Contract only: no git, environment or tool
observation is wired (`live_observation_wired: false`).

- Contracts (`src/atlas_contracts/`): `canonical.py` (one canonical JSON +
  SHA-256 helper), `execution_identity.py` (`atlas.execution-identity.v1`),
  `attestation.py` (`atlas.evidence-attestation.v1`); JSON schemas shipped
  under `atlas_contracts/schemas/`
- Function: `evaluate_proof_v2` (additive; `evaluate_proof` v1 is byte-identical
  for v1 inputs, pinned by golden digests)
- CLI: `atlas proof <task> --vault <dir> --project <id> --identity <file> --attestations <file>`
- Every attestation must bind to the identity's exact candidate HEAD/TREE and
  to the identity digest; any mismatch, tamper, or malformed input fails
  closed before anything is written
- Reports are written per object in a namespace separate from v1:
  `generated/ops/atlas3/proof/v2/<task>/<digest16>.json` (v1 stays at
  `proof/<task>.json`; `<digest16>` is a locator, the full `identity_digest`
  inside the file is the identity; a locator holding a different digest fails
  closed, never overwritten)
- Secret scanning runs over the raw string values and the task id, not only
  over escaped canonical text; findings name the pattern class only
- `result.summary` is a positive vocabulary of known counters with strict
  non-negative integers (`true`, `1.0`, `"1"` refused)
- The CLI reader refuses symlinks, inputs over 1 MiB, duplicate JSON keys and
  parser recursion exhaustion with the stable `PROOF_INPUT_INVALID` envelope
- MODEL CLAIM != PROOF (a `model` producer is refused at construction)
- `independent_of_implementer` is a producer **declaration**; v1 does not
  verify it against any principal registry (`independence_verified: false`,
  `independence_declared_only: true` in every v2 report)
- Instances passed to `evaluate_proof_v2` are re-validated from their record;
  a seal-mode draft, `model_copy` or `model_construct` cannot carry an
  unverified digest into a report
- Shipped JSON schemas pin shape only; cross-field rules and digest checks
  live in the Python contracts
- v2 task ids are safe logical identifiers (`[A-Za-z0-9][A-Za-z0-9._-]{0,127}`
  plus the shared path-component guard), decided before any filesystem access
  so Linux and Windows agree; v1's own check is unchanged
- Every proof path component under the vault is checked for symlinks with
  `lstat` before resolution; a symlink at `proof/v2`, the task directory or the
  locator is refused (`PROOF_LOCATOR_UNSAFE`), never followed. The walk starts
  at the vault root, so a vault whose `generated/`, `ops/`, `atlas3/` or
  `proof/` directory is itself a symlink is refused for v2 (v1 and other
  atlas3 writers follow it); deliberate strictness, recorded as a contract
- Evidence: `docs/evidence/AT3-103-EXECUTION-IDENTITY-PROOF-V2.md` (three
  verified objects, residual register, failure patterns); controls:
  `docs/scripts/at3_103_negative_controls.py`
- ATTESTATION != OWNER AUTHORITY; IV != MERGE; ADV != MERGE; PROOF != MERGE
- UNKNOWN ENVIRONMENT != OBSERVED ENVIRONMENT (explicit `status`, no placeholders)
- MERGE_AUTHORIZATION = NOT_GRANTED
